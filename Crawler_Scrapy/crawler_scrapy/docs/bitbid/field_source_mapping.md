# 比比网字段来源

- 招标计划：`/api/home/zbjhInfo/{id}` 的结构化字段，附件使用计划项目下载接口。
- 招标公告源栏目：`/api/home/ggInfo/{id}` 的 `ggInfo`、`xmInfo` 与
  `gongGaoNeiRong`；按标题和正文进一步区分招标公告、资格预审、更正、
  中标候选人、定标候选人及历史聚合栏目中的中标/成交结果。
- 中标候选人公示：`/api/home/hxrInfo/{id}` 的 `hxrInfo.neiRong` 与候选人公示签章PDF。
- 中标结果公示：`/api/home/zbjgInfo/{id}` 的 `zbjgInfo.neiRong` 与中标结果签章PDF。
- 公告 ID、发布日期和 PDF 文件名优先取详情接口独立字段；项目名称优先取正文
  显式标签，其次清洗公告标题，不信任历史接口中的“开标测试校验值”等占位值。
- 招标计划中复用键只有通过值域校验后才映射：项目性质仅接受“依法必须招标/非依法招标”，
  招标方式仅接受已知采购方式，项目类型不得包含 HTML 或项目概况长文，行政监督部门
  必须具有部门语义，预计发布时间必须是明确日期、月份、季度或半年。
- 项目范围、资格要求、时间、联系方式、候选人、中标人和报价按比比网正文模板分节解析；
  候选表同时支持“候选人为行”和“候选人为列”的转置表格。
- PDF是补充来源，不解析PDF.js查看器页面；爬虫直接请求原始PDF流。
- 规则出现明确质量异常时，C 方案 AI 只读取字段候选窗口并要求证据逐字回指正文；
  默认不开启，正常结构化字段不调用模型。
