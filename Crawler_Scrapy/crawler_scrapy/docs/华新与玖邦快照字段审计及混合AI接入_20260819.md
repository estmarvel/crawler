# 华新与玖邦快照字段审计及混合 AI 接入

> 日期：2026-08-19  
> 数据范围：`new_output/huaxin`、`new_output/jiubang`  
> 字段标准：`八类公告重要业务字段提取标准.md`  
> 约束：不修改数据库结构，不重写本次审计前已经保存的 JSON。

## 1. 审计范围与方法

- 华新现有 JSON 共 2748 条，其中有正文 HTML 快照 2734 条；其余 14 条为
  招标计划，源 API 本身没有公告 HTML，但完整详情 JSON 保留在 `_trace.payload.detail`。
- 玖邦现有 JSON 共 1181 条，其中有正文 HTML 快照 1170 条；其余 11 条为
  招标计划，同样以原始详情 JSON 溯源。
- 逐类型检查项目/招标编号、组织形式、地点、资格要求、招标范围、时间、
  候选人—报价、中标人—中标价、招标人及代理机构角色块。
- 第一轮按类型抽取高风险样本核对；第二轮使用当前解析器重新解析全部历史
  payload，并逐条校验独立 HTML 快照路径、SHA256、名称—报价对齐关系及明显
  标签残留，实际覆盖华新 2748 条、玖邦 1181 条。

## 2. 已发现并修复的问题

| 问题 | 审计表现 | 修复方式 |
| --- | --- | --- |
| 组织形式语义错误 | 两站把 `常规招标/重新招标/二次招标` 写入组织形式 | 不再使用 API `annNum`；只接受正文明确的 `委托招标/自行招标` 等组织形式 |
| 项目地点拼接 | 华新 744 条、玖邦 301 条出现 `中国-山西省|运城市` 一类混合值 | 优先建设/服务/交货等实际履约地点；其次使用 API 行政区；不再用竖线拼接不同层级 |
| 资格要求少提 | 华新 13 条、玖邦 15 条在存在联合体字段时只保存联合体要求 | 主体资格与联合体要求分别提取、去重后合并，并补齐“招标文件获取”等章节停止词 |
| 变更公告资格边界 | 原要求、变更后要求、监督部门和联系方式可能被一起写入 | 存在“现变更为”时只解析最后有效段，并在监督部门/联系方式前停止 |
| 开标时间误复制 | 华新 12 条、玖邦 37 条仅有截止时间却被填入开标时间 | 开标、开启和递交截止分别要求明确标签或等价 API 字段，不再互相复制 |
| 联系角色串位 | 玖邦 6 条招标人地址与代理机构地址相同，快照显示两者不同 | 增加“联系地址”标签，代理块遇到新的招标人块立即停止 |
| 机构名称重复 | 正文名称与 API 名称用 `|` 重复拼接，或联合招标人再拼牵头单位 | 正文最终公示值优先，API 只在正文缺失时兜底 |
| `u3000` 污染 | 玖邦 31 个业务字段残留错误序列化的全角空格 | 在 HTML 清洗阶段同时处理 Unicode 全角空格和字面量 `u3000` |
| 候选人名称越界 | 玖邦 14 条名称吞入报价、服务期限、工期或项目负责人 | 同时兼容有/无冒号、名次式和“第一中标候选人”式文本，并在后续业务标签前截断 |
| 候选人特殊版式漏提 | 玖邦 12 条旧结果为空；其中 10 条实际采用“推荐入围候选人1”、标题后直接列公司或无报价纵向表格 | 新增三类确定性解析；10 条全部补回，另 2 条为撤回/失败更正公告，保持空值 |
| 特殊费率报价 | 每度优惠等多分项报价不能安全换算为总金额 | 保持名称—报价索引一致；无法换算为总额时保存完整原文，不伪造 Decimal 总价 |
| 内容寻址快照被旧文件占用 | 玖邦 2 个旧 HTML 快照文件名中的哈希与文件实际 SHA256 不一致 | 快照和 payload 写入前校验已存在文件；不一致时原子替换，使后续重采可以自愈 |

项目编号与招标编号继续执行严格语义规则：优先正文明确标签，并使用经验证的
API 字段兜底；二者不会互相复制。例如玖邦公告 `1687382765118128128` 的 API
`diyProjectNo` 多一个 `0`，当前以页面明确展示的
`E140100510710116002` 为项目编号。

## 3. 混合 AI 接入范围

两站现已使用与千极链相同的 C2 证据裁决 Pipeline，并分别记录元数据：

- 华新：`field_meta.huaxinHybridAi`
- 玖邦：`field_meta.jiubangHybridAi`

AI 不处理发布网站、发布日期、快照、附件、哈希、解析版本等溯源字段，也不对
所有公告和所有字段无条件调用。只有以下情况会升级：

1. 重要字段为空且正文存在明确标签；
2. 招标范围、资格要求、项目规模等长章节出现越界标记；
3. 字段残留 HTML、错误转义、签章占位等异常内容；
4. 候选人/中标人与报价数量不一致、名称吞入报价或角色值明显冲突。

模型候选必须具有原文窗口、证据行范围、字段契约和置信度，并经过冲突裁决后
才能替换规则值；模型失败时保留规则结果，不影响公告、快照和附件保存。

## 4. GLM 与 Qwen 使用

密钥只从 `Crawler_Scrapy/.env` 读取：

```dotenv
ZHIPUAI_API_KEY=...
SILICONFLOW_API_KEY=...
```

GLM-5.2：

```bash
./run_huaxin.sh --phase notices --ai-extract --ai-provider zhipu --ai-model glm-5.2
./run_jiubang.sh --phase notices --ai-extract --ai-provider zhipu --ai-model glm-5.2
```

Qwen3-8B：

```bash
./run_huaxin.sh --phase notices --ai-extract --ai-provider siliconflow --ai-model Qwen/Qwen3-8B --ai-max-calls 0
./run_jiubang.sh --phase notices --ai-extract --ai-provider siliconflow --ai-model Qwen/Qwen3-8B --ai-max-calls 0
```

`--ai-max-calls 0` 表示不设置总调用次数上限；Qwen 仍受统一最小调用间隔、429
退避和超时保护约束。

## 5. 快照、原始响应和附件

- `annContent/annContent2` 重新启用独立 HTML 快照保存，并写入路径与 SHA256；
- 新采结果把 API 列表和详情原始对象保存到独立 `payloads/` JSON 快照，并在
  `_trace.payloadSnapshot` 记录路径与 SHA256，避免结果 JSON 重复内嵌大对象；
- 附件仍按公告详情中的 `fileId` 建立对应关系，解析实际 CDN URL 后由附件阶段下载；
- AI 不修改附件标识、URL、存储路径、哈希或下载状态。

附件完整性复核结果：华新 16 个、玖邦 18 个已记录附件的本地文件均存在，
存储路径和 MD5 校验值一致；`file_hash` 使用 Scrapy 下载校验和（MD5），数据库
字段长度可容纳，不需要改变数据库结构。

## 6. 验证结果与剩余边界

- 全项目自动化测试：`487 passed`；
- 全量历史数据按当前规则模拟时，需调用 AI 的公告占华新 5.4%、玖邦 7.3%，
  主要集中在项目规模、资格要求等长章节，未退化成全字段、全公告调用；
- 玖邦候选公示按当前规则重解析后，除 2 条源文未公布候选人的失败/更正公告外，
  其余公告均能提取候选人，且候选人名称与报价数组 100% 对齐；
- 两站全量离线复核中，上表可复现的结构性问题均已消除；
- 已保存的旧 JSON 不会被本次代码自动覆盖，重新采集或另行执行离线重解析后才会
  产生新字段结果；2 个旧玖邦快照也将在相同内容重新经过快照 Pipeline 时自愈；
- 下一步建议分别使用 GLM 和 Qwen 对每类 5 条新公告做小批量实采，核对
  `replacedFields`、证据行与模型 token，再决定全量运行。
