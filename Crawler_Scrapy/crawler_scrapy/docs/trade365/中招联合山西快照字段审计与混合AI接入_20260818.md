# 中招联合山西快照字段审计与混合 AI 接入（2026-08-18）

## 范围与方法

- 只读取 `new_output/trade365` 的 60 条历史 JSON 和 60 份 HTML 快照；
- 以快照重放当前解析器，对照八类公告字段标准和数据库现有公告类型编码；
- 不请求网站、不调用模型、不回写历史 JSON、不写数据库；
- 修改范围仅为站点解析、导出路由、Spider AI 配置、测试和文档。

## 历史问题

1. 60/60 条历史记录把栏目属性“招标信息”写入`项目性质`，不符合项目性质枚举；
2. 9 条变更、5 条终止历史记录按 `TENDER` 保存，1 条“中标候选人公示更正”按
   `CANDIDATE` 保存，均应使用 `更正结果公示/CORRECTION`；
3. 招标公告在正文未披露开标/开启时间时会把投标截止时间复制过去，造成语义伪填；
4. AI 配置会对每条招标公告固定复核范围、资格字段，模型调用面大于实际需要。

## 修复结果

- 变更、延期、控制价、澄清、答疑、补充、终止、废标、流标、撤销、暂停及候选人更正
  统一进入 `correction.*` 路由和 `CORRECTION` Schema；
- `公共类型`限定为字段标准允许值，`公告内容`只保存更正事项，排除联系方式和签章页脚；
- `项目性质`无依法/非依法明确证据时留空；截止时间不再伪填开标时间；
- `_trace.fieldMeta`分别保留源栏目公告类型和最终 Schema 类型；
- 项目编号、招标编号继续按明确标签分离，API/源字段与正文证据不互相猜测；
- 旧 JSON 未被修改，离线原地重算遇到 Schema 迁移会安全拒绝。

## AI 接入策略

已复用 Qianji 验证过的 C 方案混合抽取管线，但不把全部 HTML 和全部字段交给模型：

- 正常规则字段不调用 AI；
- 仅主要字段出现“有标签未命中、HTML 残留、章节越界、名单与报价错位”等异常时升级；
- 提交字段标签附近的候选窗口，不提交整页导航、样式和签章模板；
- 规则值与 AI 值都必须有正文证据，AI 可纠正规则误取，但不能覆盖可信发布日期等源元数据；
- 本次离线审计未调用模型，因此 token 消耗为 0。
