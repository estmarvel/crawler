# 千极链字段质量审计与混合 AI 方案

## 1. 历史样本审计结论

审计范围为 `new_output/qianji/json` 的 13 个文件、65 条公告。审计使用保存的详情 API
payload、正文和 HTML 快照，只读比较，不覆盖历史 JSON，不写数据库。

已经确认的语义或提取问题：

| 问题 | 影响数量 | 原因 | 新规则 |
| --- | ---: | --- | --- |
| 将栏目“工程/货物/服务”写入“所属行业” | 30 | 项目类型与行业混用 | 栏目类型只留在公告子类型；所属行业仅取正文明确标签 |
| 将 `projectCode` 写入结果公告“依据文号” | 15 | 项目编号与批准文号混用 | 依据文号仅取“依据文号/批准文号”标签 |
| 项目编号使用正文代理编号或标段编号 | 3 | 没有优先使用 API `projectCode` | `projectCode` 存在时作为项目编号并记录来源 |
| 正文已有招标编号但 JSON 为空 | 5 | 标签变体、标签和值分行 | 支持独立小标题、下一段取值及精确标签 |
| “总投资额”漏提 | 1 | 标签词典缺少变体 | 增加“总投资额”，保留单位及括号说明 |

金额、报价和日期的其余大量差异主要是新旧 JSON 序列化形式不同，例如 Decimal 与数字、
秒和毫秒显示差异，不应直接计为字段语义错误。

## 2. 为什么不能只让 AI 补空字段

只补空字段只能提升完整率，无法发现规则的边界截断、角色串位或字段语义混用。新的千极链
流程让规则先解析完整 HTML，AI 只阅读字段候选窗口，然后比较结果：

```text
详情 API
  ├─ 普通结构化字段 ──> 直接采用并锁定
  └─ Base64 content ──> HTML 解码/正文 ──> 站点规则候选
                                      │
                                      └─> 标签/章节/规则值定位
                                             │
                                             v
                                      1~2 个候选窗口
                                      + window_id/偏移
                                             │
                                             v
                                      GLM-5.2 抽取 + 逐字证据
                                             │
                    一致/高置信补空 ─────┼───── 冲突/低置信/证据失败
                           直接验收          │        扩大到完整相关章节
                                             │                 再抽取
                                             v
                              证据 + 字段契约 + 类型校验
                                             │
                              通过才允许补空或纠正规则
```

API 可信字段不会被 AI 修改。AI 候选必须提供正文逐字证据；证据不在正文、值不受证据支持或
字段不在网站白名单时直接拒绝。模型证据在 JSON 中只保存正文偏移、SHA256 和短预览，避免
重复保存整段正文。

字段定义、排除项、AI 分级和地点粒度由
`八类公告重要业务字段提取标准.md` 统一约束，代码实现位于
`crawler_scrapy/ai/field_contracts.py`。

## 3. 采用的论文方法

- [GoLLIE（ICLR 2024）](https://openreview.net/forum?id=Y3wpuxd7u9)：详细标注指南是
  零样本信息抽取的重要因素。因此每个字段配置独立语义、正例边界和禁止混淆项。
- [GPT-NER（NAACL 2025）](https://aclanthology.org/2025.findings-naacl.239/)：使用
  self-verification 降低模型在空值上的幻觉。这里将其用于规则/AI冲突的第二次批量核验。
- [InstructUIE](https://arxiv.org/abs/2304.08085)：使用统一指令和统一结构表达多类信息
  抽取任务。这里按公告 Schema 生成目标字段，不允许模型返回额外字段。
- [Lost in Formatting（EACL 2026）](https://aclanthology.org/2026.eacl-long.256/)：输出
  格式本身会显著影响 IE 效果。因此固定使用 JSON object，并对格式、字段集合和类型做校验。
- [ExtractBench](https://arxiv.org/abs/2607.29677)：同时评估值准确率、完整率、证据
  grounding 和成本。千极链评测也分别记录这些指标，而不是只统计“填了多少字段”。

## 4. 测试与验收指标

在线测试必须使用隔离输出目录，并至少统计：

1. 字段级 exact/规范化匹配准确率；
2. 多值字段的 precision、recall、F1 及顺序/角色对应；
3. 非空字段完整率；
4. 证据回查通过率；
5. 规则与 AI 一致率、AI 正确纠错率、AI 错误覆盖率；
6. 每条公告调用次数、token 和耗时。

上线门槛不应只看完整率。尤其是编号、单位名称、候选人/报价、中标人/中标价等关联字段，
AI 错误覆盖率必须为零或进入人工复核，不应自动导入数据库。

## 5. 30 条/一级类别实测（2026-08-14）

> 本节是切换 GLM-5.2 之前使用 Qwen3-8B 得到的历史基线，不能作为
> GLM-5.2 或候选窗口 v6 的效果结论。

隔离目录 `new_output/qianji_ai_validation_30_v4/qianji` 共保存 150 条：招标计划、招标公告、
变更公告、中标候选人公示、结果公示各 30 条；工程/货物/服务子类型各 10 条。测试不下载
附件、不写数据库。

验收结果：

- 150/150 条规则解析状态为 `PARSED`，AI 最终状态为 `SUCCESS`；免费接口超时项通过
  payload 快照离线补偿，不重新抓取公告；
- AI 有证据地补空 49 个字段、纠正规则边界 37 个字段；另有 9 个冲突因 AI 结果不完整
  或语义不符而继续保留规则值；
- 150/150 份 HTML 快照和 payload 快照路径、SHA256 有效；150/150 个 API `projectCode`
  未被 AI 改写；所有已采用 AI 候选均有可定位的正文证据；候选人/报价、中标人/中标价
  数量配对检查全部通过；
- 实际纠正包括项目/建设地点、建设规模、资金来源、文件获取/递交方法、保证金方式、
  中标联合体和服务期；实测还反向修复了整点时间、`递交的截止时间`、`提交保证金的方式`
  等规则变体；
- 对同一批正文应用新的稀疏字段策略后，每条模型目标字段预计从 8.31 降到 4.76，目标字段
  总量下降 42.7%。模型仍复核所有实际命中的高风险规则字段，不再为大量不存在的项目经理、
  依据文号等字段反复输出空值。

本节数据是 C 方案上线前的 v4/v5 基线，不是候选窗口 v6 的
新速度或准确率结论。上述结果证明混合流程比“规则值永不覆盖”更能纠正边界错误，但不能把 150 条样本视为所有
未来模板的永久准确率保证。后续应持续按公告类型抽样正文，并把新增反例固化为规则、字段
语义校验和单元测试。

## 6. C2 方案实现状态

- 候选窗口保存 `windowId/start/end/fields/stage/mode/chars`；
- 模型输入窗口逐行标记 `L001...`，输出只保留窗口和起止行；长字段由程序从原文切片，
  不再让模型重复生成整段正文；
- 短字段首轮取标签前 1 行、后 3 行，长字段首轮直接取完整章节；
- 一篇中字段出现多次时优先保留首尾窗口，覆盖变更前后值；
- 冲突或证据失败的字段才执行第二次章节级抽取；只有首轮和扩展阶段语义一致时，
  才能自动覆盖非空规则结果；
- 项目地点和建设地点在本地最终规范化为省/市/区县，不保存乡镇村；
- 八类公告全部预设字段均有显式类型、定义和候选标签；金额仍由本地换算后匹配
  数据库 `Decimal(18,2)`，时间、字符串和数组不改变数据库结构；
- 编号、人民币金额单位、候选人-报价数组、证据偏移和长章节完整性继续由本地验证；
- 名称和报价的 C2 候选必须来自同一窗口和相同行范围，避免只按数组长度错误配对；
- AI 失败时保留规则结果，不影响公告、快照和附件存储。
