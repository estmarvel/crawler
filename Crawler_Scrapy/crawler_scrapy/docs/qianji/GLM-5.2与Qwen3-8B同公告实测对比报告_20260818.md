# GLM-5.2 与 Qwen3-8B 同公告实测对比报告

> 测试日期：2026-08-18  
> 测试站点：千极数采电子交易平台（Qianji）  
> 数据库：未写入、未修改结构

## 1. 测试方法

从千极数 13 个实际数据源各取最新 1 条，覆盖招标计划，以及工程、货物、
服务三类的招标、变更、候选和结果公告。GLM-5.2 与 Qwen/Qwen3-8B 使用
相同查询条件连续实采，并写入相互隔离的输出目录：

- `new_output/qianji_ab_glm_v2_20260818/qianji`
- `new_output/qianji_ab_qwen_v2_20260818/qianji`

两组公告 ID 交集为 13/13，HTML SHA256 和正文 SHA256 均为 13/13 相同，
因此模型收到的业务正文完全一致。逐条对照 JSON、正文、HTML 快照、原始
API payload 和 AI 证据行进行判断，而不是把“两模型结果相同”直接视为正确。

## 2. 优化后实测指标

| 指标 | GLM-5.2 | Qwen3-8B |
|---|---:|---:|
| 公告数 | 13 | 13 |
| 进入混合 AI 的公告 | 8 | 8 |
| AI 成功 / 失败 / 无窗口跳过 | 6 / 0 / 2 | 6 / 0 / 2 |
| 模型请求 | 10 | 11 |
| 输入 Token | 8,870 | 11,315 |
| 输出 Token | 1,441 | 2,084 |
| 总 Token | 10,311 | 13,399 |
| 最终填充字段 | 1 | 1 |
| 最终替换规则字段 | 2 | 5 |
| 总耗时 | 111.26 秒 | 120.64 秒 |
| 平均每条 | 8.56 秒 | 9.28 秒 |

Qwen 优化前同批耗时 232.12 秒且有 1 条超时失败；优化后没有失败，总耗时
降至 120.64 秒，接近 GLM。本批 Qwen 总 Token 比 GLM 高 29.9%，主要是严格
JSON Schema 的字段对象和证据行输出较长，不是传入了整篇 HTML。免费端点
存在队列波动，因此两轮耗时差不能全部归因于代码优化。

## 3. 字段质量对比

优化后的第二轮中，两模型最终业务字段只有同一条工程招标公告的 3 个字段
不同：

| 字段 | GLM-5.2 | Qwen3-8B | 快照审计结论 |
|---|---|---|---|
| 获取方式 | 带“凡有意参加投标者、文件发布时间内”的完整句 | `通过千极数采电子交易平台网上下载招标文件` | Qwen 更贴合“只保存获取操作” |
| 递交方法 | 保留平台工具、编制、签章、CA 加密上传全过程 | 只保留 `上传经 CA 数字证书加密的投标文件` | Qwen 丢失明确的平台渠道；已增加校验，后续会拒绝该短候选并保留完整规则值 |
| 投标保证金方式 | 方法列表后带“等非现金交易担保方式” | 只保留现金、汇款/支票、银行保函、电子保函 | Qwen 更贴合“只保存担保方式” |

Qwen 优化后没有再产生字符串 `"null"`、HTML 标签值或无原文证据的最终覆盖。
项目编号继续信任已验证的 API `projectCode`；招标编号只来自正文明确标签，
两者没有互相复制。候选人/中标人及报价保持原始顺序，未发现列表错位。

## 4. 根据快照发现并修复的共同规则问题

本次同时发现了不能交给模型兜底的确定性问题，均已放回规则层：

1. `项目总投资(万元/人民币) = 440` 原被当作 440 元，现按单位转换为
   `4,400,000.00` 元；
2. 正文预计发布时间 `20260510000000` 原退化为 API 月份 `202605`，现保留为
   `2026-05-10`；
3. 项目地点优先正文明确的建设地址，不再优先更泛的顶部行政地区；
4. 资金来源在逗号后的招标人/采购人角色处截断，不再依赖 AI 清除；
5. 投标保证金只保存方式列表，删除序号、“本项目可以采用”和“提交投标
   保证金”等说明套话；
6. API 的“依法招标/非依法招标”分别映射为字段契约允许的“依法必须招标/
   非依法招标”，不再因枚举别名不一致落为空值。

## 5. Qwen 专属优化

- 关闭思考并使用零随机性，保留严格字段级 JSON Schema；
- 明确禁止把 JSON `null` 输出成字符串，并在程序侧再次规范；
- 对资金来源、保证金和递交方法增加模型专属边界说明；
- 递交方法必须保留正文明确的平台、线上/线下、现场或邮寄渠道；缺渠道的
  AI 候选不能覆盖规则；
- 单次输出上限调整为 2,200 token，单次超时为 60 秒；
- 硅基流动免费端点发生超时时不立即重复相同请求，避免一条公告连续等待
  120 秒；其他可恢复错误仍保留一次有限重试；
- AI 失败时继续保存规则结果、HTML 快照、payload 和失败元数据，公告不会
  因模型不可用而丢失。

## 6. 最终判断

Qwen3-8B 在本批短字段清洗上有实际价值，尤其是获取方式和保证金方式；经
严格证据和渠道完整性校验后，可以用于全量采集。它的最终字段质量已接近
GLM-5.2，但免费端点仍有偶发排队超时，且同批 Token 高于 GLM。因此推荐将
Qwen 用作低成本全量混合解析模型，同时保留规则结果作为故障回退；对质量
复核或高价值批次仍可切回 GLM-5.2。

本结论只覆盖本次 13 条同公告样本，不能代替后续新模板的小批量快照回归。
