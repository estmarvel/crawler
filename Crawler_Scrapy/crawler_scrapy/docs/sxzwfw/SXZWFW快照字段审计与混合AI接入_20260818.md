# SXZWFW 快照字段审计与混合 AI 接入（2026-08-18）

## 范围与方法

- 流式扫描 `new_output/sxzwfw` 的 20,717 条历史记录，避免一次加载 1.6GB JSON；
- 按历史子类型固定随机种子分层抽取 53 条，并读取对应 HTML 快照重放解析；
- 全部 20,717 条记录均有对应快照；本轮不请求网站、不调用模型、不回写 JSON、不写数据库。

历史子类型分布：招标计划 7,769、资格预审 211、招标公告 12,442、旧终止类 282、
误归合同与履约 13。

## 历史问题

按标题和源栏目用新规则扫描，发现以下旧类型需要纠正：

| 历史编码 | 新编码 | 数量 | 原因 |
| --- | --- | ---: | --- |
| `PREQUALIFICATION` | `CORRECTION` | 15 | 资格预审更正/变更类标题 |
| `TENDER` | `CORRECTION` | 3,696 | 控制价、最高限价、延期、撤销等 |
| `TERMINATION` | `CORRECTION` | 282 | 终止/废标统一使用现有更正 Schema |
| `CONTRACT` | `PLAN` | 7 | 项目名中的“合同包/合同段”被误判 |
| `CONTRACT` | `TENDER` | 5 | 招标项目名称中的“合同段”被误判 |
| `CONTRACT` | `CORRECTION` | 1 | 含“合同段”的招标控制价被误判 |

关键字计数允许交叉，不能直接相加；其中“招标控制价”3,337 条、“最高投标限价”170 条，
是旧招标公告文件中最主要的分类偏差来源。

## 修复结果

- 招标控制价、最高投标限价、更正、变更、撤销、澄清、答疑、延期、终止、废标、流标、
  招标失败和重新招标统一进入 `gzjg/更正结果公示/CORRECTION`；
- `公共类型`输出标准枚举；正文“有效投标人不足三家”映射为`废标公告`；
- `公告内容`从更正/控制价事项开始，在监督部门、联系方式或签章前停止；
- 最终开标/开启/截止时间取有标签的最后一个时间，避免保存更正前旧值；
- `招标撤销（终止）公告、招标控制价公示、最高投标限价公示`等后缀从项目名删除；
- 只有明确“合同公告、合同签订、履约公告/验收”才使用合同 Schema，“合同段/合同包”不触发；
- 工程和政府采购更正解析器使用同一 `公共类型`与公告内容边界标准；
- 源栏目、源公告性质和最终 Schema 继续保存在 `_trace.fieldMeta`，数据库结构未改变。

## AI 与附件

- 已接入通用 C 方案；正常规则结果不调用模型；
- 更正内容、合同内容、范围、资格、名单/金额等主要字段只有在标签未命中、HTML 残留、
  章节污染或数组错位时才提交候选窗口；
- AI 能以更强证据纠正规则误取，但不能覆盖可信发布日期等源元数据；

- CMS 附件元数据解析、公开直链识别、附件独立下载和 JSON 回写逻辑保持不变。
