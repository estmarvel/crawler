# 山西省公共资源交易平台政府采购采集说明

## 当前接入范围

政府采购与工程建设共用服务端 HTML 列表、分页和详情页骨架，但业务模板不同。当前只接入：

| 框架栏目 | channelId | 源站栏目 | 保存 Schema |
| --- | ---: | --- | --- |
| `zc_gz` | 19 | 更正公告 | 更正结果公示 |
| `zc_jg` | 20 | 中标结果公告 | 中标结果公示 |

`channelId=18` 采购公告暂不采集，也没有加入 Spider 可运行栏目。未显式传 `sections` 时，
`sxzwfw` 仍只运行工程建设默认六类，不会自动混入政府采购。

## 已接入栏目的请求方式

列表使用与前端一致的表单：

```text
POST https://prec.sxzwfw.gov.cn/queryContent-jyxx.jspx
title=
channelId=19 或 20
inDates=
beginTime=YYYY-MM-DD
endTime=YYYY-MM-DD
origin=
ext=
```

第二页起请求 `/queryContent_2-jyxx.jspx`、`/queryContent_3-jyxx.jspx`。每页 10 条，
详情直接 GET 列表中的 `.jhtml`，不使用 Token、浏览器渲染或虚构 JSON API。

更正公告一律进入“更正结果公示”预设字段：`公共类型`保留更正、废标、终止、撤销、
延期、澄清等源站语义，正文写入`公告内容`，同时提取项目名称、开标/响应截止时间、
采购人联系方式、采购代理机构、监督部门、发布日期、发布网站和附件。

结果公告进入“中标结果公示”预设字段。供应商与成交金额按同一表格行构造成
`中标结果明细`，再生成名称和金额数组，缺失金额时保留空位，不会错配。采购人、代理机构
和项目联系人按三个章节边界提取。详情 HTML 保存快照，外链 PDF 只下载归档，不做 OCR。

政府采购两类各 5 条的独立验收测试：

```bash
cd /home/intsig/Crawler_Scrapy
./run_sxzwfw.sh --phase notices --sections zc_gz,zc_jg \
  --days 365 --max-records 5 --output-root /tmp/sxzwfw_government_test
```

上述命令在最近 365 天内获取每类最新 5 条，共 10 条，并写入独立临时目录，
不会混入正式 `new_output`。采集后可运行站点审计器核对关键字段、供应商—金额配对、
HTML 快照和附件清单。

## 采购公告 channelId=18 预留方法（当前禁用）

以后启用采购公告时，列表仍使用同一个 POST 接口，只把 `channelId` 设为 `18`。
项目类型筛选为：`D01` 货物、`D02` 工程、`D03` 服务；完整采集时 `ext` 留空。

详情仍使用：

```text
标题：.cs_title_P1
发布时间和来源：.cs_title_P3
正文：.cs_xq_content .div-article2
附件：正文附件区域和通用 a[href] 文件链接
```

计划字段映射如下，但在数据库字段方案确认前不写入代码：

| 政府采购字段 | 预设字段/处理方式 |
| --- | --- |
| 项目编号 | 项目编号/招标编号 |
| 项目名称 | 项目名称 |
| 预算金额 | 项目总投资/估算金额或招标金额，启用前需最终确认 |
| 采购需求 | 招标内容与范围 |
| 合同履行期限 | 工期/服务期/供货日期 |
| 供应商资格要求 | 申请人资格要求/投标人资格要求 |
| 采购文件获取时间、方式 | 预审文件获取时间、获取方式 |
| 响应截止时间、开启时间/地点 | 递交截止时间、开启时间、开启地点 |
| 采购人、代理机构 | 对应招标人/采购人及代理机构字段 |
| 采购方式、最高限价 | 当前预设字段不足，启用前需确定保存字段 |

启用前至少需要补充公开招标、竞争性磋商及其他采购方式的详情样本，验证预算、最高限价、
文件获取、响应截止、联合体要求和联系方式模板。确认后再增加 `zc_cg -> channelId=18`，
不能临时复用工程建设规则，以免把采购方式写成组织形式或错误解释预算金额。
