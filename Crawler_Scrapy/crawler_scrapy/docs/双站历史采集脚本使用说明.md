# 双站历史采集脚本使用说明

本文说明如何使用 `run_tws_history.sh` 批量采集华新阳光采购平台和玖邦招标采购电子交易平台的历史公告。

## 1. 脚本位置与基本运行方式

脚本位置：

```text
/home/intsig/Crawler_Scrapy/run_tws_history.sh
```

脚本固定通过 `myenv` 环境运行，无需手动执行 `conda activate`。进入项目目录后即可运行：

```bash
cd /home/intsig/Crawler_Scrapy
./run_tws_history.sh --days 180
```

不带参数运行时也默认采集最近 180 天：

```bash
./run_tws_history.sh
```

查看脚本参数：

```bash
./run_tws_history.sh --help
```

## 2. 可用参数

| 参数 | 含义 | 默认值 | 示例 |
|---|---|---|---|
| `--all` | 不设开始时间，逐栏目翻到源站最后一页，采集全部历史 | 关闭 | `--all` |
| `--days N` | 从当前时间或指定结束时间向前采集 N 天 | `180` | `--days 30` |
| `--start-date` | 明确指定开始日期；指定后开始时间不再由 `--days` 决定 | 空 | `--start-date 2026-01-16` |
| `--end-date` | 指定结束日期，日期当天按 23:59:59 处理 | 当前时间 | `--end-date 2026-07-16` |
| `--sites` | 选择网站，多个值用英文逗号分隔 | `huaxin,jiubang` | `--sites huaxin` |
| `--sections` | 选择上游栏目，多个值用英文逗号分隔 | 四个栏目 | `--sections hxr,gs` |
| `--output-root` | 自定义结果根目录 | 项目下的 `output` | `--output-root /data/crawler` |

日期建议使用 `YYYY-MM-DD`。如果需要精确到时间，Spider 也支持 `YYYY-MM-DD HH:MM:SS`，此时参数值必须用引号包住。
`--all` 与 `--days`、`--start-date`、`--end-date` 互斥，避免把“全量”和时间窗口混为一次任务。

## 3. 网站和栏目代码

网站代码：

| 代码 | 网站 |
|---|---|
| `huaxin` | 华新阳光采购平台 |
| `jiubang` | 玖邦招标采购电子交易平台 |

栏目代码：

| 代码 | 内容 |
|---|---|
| `zbgg_zys` | 招标公告和资格预审公告 |
| `hxr` | 中标候选人公示及其更正、撤销等细分类别 |
| `gs` | 中标结果公示及其更正、撤销等细分类别 |
| `zbjh` | 招标计划及招标计划变更 |

当前脚本只采集两个网站的招投标模块，不采集独立采购、竞价和零散采购模块。

## 4. 不同场景的运行命令

### 4.1 两个网站补采全部历史

使用当前 `output` 目录继续采集，不要删除已经完成的 180 天结果：

```bash
cd /home/intsig/Crawler_Scrapy
./run_tws_history.sh --all
```

脚本会从每个栏目最新页一直翻到源站最后一页。现有去重索引会在列表阶段跳过
“已经保存且列表信息未变化”的公告详情，较早公告会追加到原 JSON/CSV；同一公告内容后来
发生变化时会追加一个新版本，不覆盖历史版本。

### 4.2 两个网站采集最近 180 天

适合日常首次执行或不要求严格按自然月计算的场景：

```bash
cd /home/intsig/Crawler_Scrapy
./run_tws_history.sh --days 180
```

`180 天`不完全等于`六个自然月`。如果要求准确覆盖某个自然日期区间，应使用起止日期。

### 4.3 两个网站采集准确的六个月区间

例如采集 2026 年 1 月 16 日至 2026 年 7 月 16 日：

```bash
./run_tws_history.sh \
  --start-date 2026-01-16 \
  --end-date 2026-07-16
```

开始日期包含当天 00:00:00，结束日期包含当天 23:59:59。

### 4.4 只采集华新

```bash
./run_tws_history.sh --days 180 --sites huaxin
```

### 4.5 只采集玖邦

```bash
./run_tws_history.sh --days 180 --sites jiubang
```

### 4.6 只采集候选人公示和结果公示

```bash
./run_tws_history.sh --days 180 --sections hxr,gs
```

### 4.7 只采集招标公告和资格预审公告

```bash
./run_tws_history.sh --days 180 --sections zbgg_zys
```

### 4.8 只采集招标计划

```bash
./run_tws_history.sh --days 180 --sections zbjh
```

### 4.9 先进行小范围正式链路检查

脚本按时间而不是按条数运行。首次更换代理或修改代码后，可以先采集最近 1 天：

```bash
./run_tws_history.sh --days 1
```

也可以仅检查一个网站的一个栏目：

```bash
./run_tws_history.sh --days 1 --sites huaxin --sections gs
```

这仍会正常请求列表、详情和附件，只是时间范围较小。

### 4.10 指定历史截止时间

以 2026 年 6 月 30 日为截止日期向前采集 90 天：

```bash
./run_tws_history.sh --days 90 --end-date 2026-06-30
```

脚本会以结束日期当天 23:59:59 为基准向前计算 90 天，并过滤结束日期之后的公告。

### 4.11 自定义输出目录

```bash
./run_tws_history.sh \
  --days 180 \
  --output-root /home/intsig/crawler_history_output
```

自定义目录下仍会按 `huaxin`、`jiubang`、`logs` 分开保存。

### 4.12 全量任务放到后台运行

六个月数据可能需要较长时间，可以使用 `nohup`：

```bash
cd /home/intsig/Crawler_Scrapy
nohup ./run_tws_history.sh --all > full_history_runner.log 2>&1 &
```

查看启动器日志：

```bash
tail -f /home/intsig/Crawler_Scrapy/full_history_runner.log
```

启动器日志之外，每个网站仍有独立的正式日志文件。

## 5. 时间边界和停止规则

每个网站、每个栏目都从最新一页开始向历史数据翻页，并独立判断何时停止：

1. 公告发布日期早于开始时间时，不保存该公告。
2. 正常倒序页面已经越过开始时间时，该栏目停止翻页。
3. 如果页面日期顺序异常，例如存在置顶旧公告，不会因为单条旧公告提前停止。
4. 如果列表记录缺少可解析日期，会请求详情并合并数据后再次判断，避免漏采。
5. 如果某个栏目本身只有少量公告，尚未到达开始时间就已经到达最后一页，该栏目自然结束。
6. 一个栏目结束不会影响同一网站其他栏目的运行。

因此，“要求采集六个月，但网站该栏目实际只有三个月数据”的情况，会保存该栏目现有的全部三个月数据，然后在源站最后一页停止。

## 6. 并发与访问保护

脚本采用两层并行：

- 华新和玖邦各运行一个独立 Scrapy 进程，两个网站并行。
- 每个网站的四个栏目在同一个进程中并行调度，避免多个进程同时写同一网站的 JSON/CSV。

当前保护参数：

- 单网站总并发：4。
- 单域名并发：2。
- 基础请求延迟：2 秒，并开启随机延迟。
- AutoThrottle 初始延迟：3 秒，目标并发：1，最大延迟：60 秒。
- 普通请求最多重试 2 次。
- direct 模式收到 403/429 后设置 120～900 秒保护延迟，并在首次连续限制响应时主动停止。
- static/tianqi 备用模式仍采用连续 2 次或累计 4 次后停止的原有阈值。

这些设置用于降低请求频率和及时响应限流，但任何公网采集都不能绝对保证目标站永不封禁出口 IP。

不要同时启动两个包含同一网站的脚本。例如，第一个任务正在采集 `huaxin` 时，不要再启动另一个 `--sites huaxin`，否则两个进程可能同时追加同一组输出文件，也会使请求频率翻倍。

## 7. 服务器直连保护与代理备用模式

脚本现在默认使用服务器公网出口：

```bash
./run_tws_history.sh --outbound-mode direct --days 1 --sites huaxin --sections gs \
  --page-size 10 --max-records 1 --max-pages 1
```

直连模式强制使用单并发、同域名单并发、5 秒随机基础延迟和 AutoThrottle；普通失败不重试，首次连续出现 403/429 即主动停止。建议始终先用单栏目、单页、1 条进行连通性验证。

如需切回固定代理：

```bash
HUAXIN_PROXY_ENDPOINT='http://新地址:端口' \
HUAXIN_PROXY_USERNAME='新账号' \
HUAXIN_PROXY_PASSWORD='新密码' \
./run_tws_history.sh --outbound-mode static --days 1
```

代理更换后建议先使用 `--days 1 --sites huaxin --sections gs` 做小范围链路检查。

固定代理返回 407 时，也可以复用项目已有的天启代理池：

```bash
export TIANQI_SECRET='...'
export TIANQI_SIGN='...'
./run_tws_history.sh --outbound-mode tianqi --days 1 --sites huaxin --sections gs
```

`direct`、`static` 和 `tianqi` 共用相同的限速和访问限制保护；其中 direct 使用当前服务器 IP。

## 8. 输出文件和日志

使用默认输出目录时：

```text
output/
├── huaxin/
│   ├── json/
│   ├── csv/
│   ├── attachments/
│   └── state/
├── jiubang/
│   ├── json/
│   ├── csv/
│   ├── attachments/
│   └── state/
└── logs/
    └── YYYYMMDD_HHMMSS/
        ├── huaxin.log
        └── jiubang.log
```

- JSON 和 CSV 按网站、公告类型追加保存。
- 附件只下载原文件，不执行 OCR 或 AI。
- 华新和玖邦不保存 HTML 快照。
- 每条导出数据保留“爬虫时间”。
- `state/notice_versions.json` 用于跨运行公告版本去重。
- `state/jobs/<时间窗口>/` 用于中断续跑。

全量任务使用独立的 `state/jobs/all/` 恢复目录，不会混用此前 `days_180` 的调度队列；
两种任务继续共享 `notice_versions.json`，所以 180 天内已成功保存的内容仍会被识别并跳过。

终端会同时显示两个网站的运行日志；需要单独排查某个网站时，应打开对应站点日志文件。

## 9. 去重、重复执行和中断续跑

### 相同命令重复执行

重复执行相同时间范围命令是安全的：

```bash
./run_tws_history.sh --days 180
```

- 相同公告且内容未变化：不会重复写入。
- 相同公告但正文或结构化内容发生变化：追加一个新版本，保留旧版本。
- 新公告：追加到现有 JSON/CSV。
- 已下载的同一源站附件：复用稳定文件路径，不重复覆盖。

### 中断后继续

按 `Ctrl+C` 停止或进程意外退出后，重新执行完全相同的命令：

```bash
./run_tws_history.sh \
  --start-date 2026-01-16 \
  --end-date 2026-07-16
```

相同网站和时间窗口会使用相同的 Job 状态目录，并结合公告版本去重继续执行。不同时间窗口使用不同 Job 状态目录，互不混用。

全量任务中断后直接重新运行同一命令：

```bash
./run_tws_history.sh --all
```

如果明确要完全重新调度同一时间窗口，可以先删除对应的 `state/jobs/<时间窗口>/`；一般情况下不需要删除，公告版本去重仍会保护已有结果。

## 10. 判断运行结果

正常完成时，终端末尾会显示：

```text
huaxin 采集完成
jiubang 采集完成
本次日志目录：...
JSON/CSV和附件目录：...
```

脚本退出码：

- `0`：所选网站均以 `finish_reason=finished` 正常完成。
- `1`：至少一个网站采集失败、日志写入失败或被访问保护主动停止。
- `2`：命令参数错误。
- `130`：收到人工终止信号。

## 11. 常见问题排查

### 一直没有新数据

检查：

1. 时间范围内是否确实存在公告。
2. 是否已在之前运行中保存过相同内容，因去重而未重复写入。
3. 日志中栏目结束原因是否为 `time_boundary_reached` 或 `source_exhausted`。

### 出现代理连接、407 或认证错误

固定代理可能失效或账号密码不正确。更新代理后先运行：

```bash
./run_tws_history.sh --days 1 --sites huaxin --sections gs
```

默认 direct 不需要代理；只有显式选择 static/tianqi 时才检查对应凭据。

### 出现 403/429

脚本会自动退避；达到阈值后主动停止该网站。此时不要立即高频重启，应先查看独立日志，确认代理状态并等待一段时间后再继续。

### 一个网站完成，另一个网站失败

两个网站是独立进程。已完成网站的数据会保留，失败网站可以之后通过 `--sites` 单独继续：

```bash
./run_tws_history.sh --days 180 --sites jiubang
```

### 日志显示 `source_exhausted`

表示源站已经到达最后一页或返回数量不足一整页，是正常停止条件，不代表爬虫错误。

### 日志显示 `time_boundary_reached`

表示该栏目已经翻到指定开始日期之前，是正常完成历史区间采集。

## 12. 推荐的全量执行流程

1. 先检查一天、一个网站、一个栏目：

   ```bash
   ./run_tws_history.sh --days 1 --sites huaxin --sections gs
   ```

2. 确认日志、JSON、CSV 和附件正常后，运行全部历史：

   ```bash
   nohup ./run_tws_history.sh --all > full_history_runner.log 2>&1 &
   ```

3. 分别查看华新和玖邦日志，重点关注代理错误、403、429、详情 API 错误和附件下载失败。
4. 任务结束后确认两个网站均显示“采集完成”，再统计各公告类型的 JSON 条数和附件下载状态。
