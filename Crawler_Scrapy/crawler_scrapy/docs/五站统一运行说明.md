# 六站统一公告与附件运行说明

本文重点说明统一入口和通用参数。各站接口、栏目、字段规则及附件实现见
[《五站爬虫详细实现说明》](五站爬虫详细实现说明.md)。

## 入口

六个网站各保留一个运行脚本，底层共享 `crawler_scrapy.site_runner`，避免限速、
断点、快照和附件逻辑出现多份不一致实现。

```bash
./run_sxjm.sh
./run_sxzwfw.sh
./run_bitbid.sh
./run_huaxin.sh
./run_jiubang.sh
./run_qianji.sh
```

默认 `--phase all`：先完成公告、正文、HTML 快照、附件清单和 JSON/CSV 导出，
公告阶段正常结束后再独立下载附件并回写同一公告。文件下载慢不会占用公告 Spider。

## 常用配置

```bash
# 最近 30 天，只采指定栏目
./run_sxzwfw.sh --days 30 --sections zbgg_zys,hxr,gs

# 精确日期
./run_bitbid.sh --start-date 2026-07-01 --end-date 2026-08-05

# 源站全部历史
./run_sxjm.sh --all

# 公告和附件分开运行
./run_huaxin.sh --phase notices --days 180
./run_huaxin.sh --phase attachments

# 调整数量和分页
./run_jiubang.sh --max-records 500 --max-pages 50 --page-size 50
```

全部参数可运行 `./run_<site>.sh --help` 查看。栏目默认值：

- SXJM：`zbgg,cggg,hxr,cjhxr,zbjg,cjgg,zbjh,zzgg`；还可用 `--channels`。
- SXZWFW：`zbjh,zbgg_zys,bg,hxr,gs,qt`；政府采购可传 `zc_gz,zc_jg`。
- Bitbid：参数名仍统一写作 `--sections`，值为 `plan,tender,candidate,award`。
- Huaxin、Jiubang：`zbgg_zys,hxr,gs,zbjh`。
- Qianji：`plan,tender,change,candidate,award`；还可用 `--project-types`
  选择 `engineering,goods,service`。

## 限速与出口

默认并发为 2。每批从 3~5 秒中随机选择实际请求间隔，400 个响应后冷却
180~300 秒；AutoThrottle 在源站变慢时继续降速。403/429 或固定代理认证失败会停止，
不会持续重试冲击出口。

```bash
./run_sxjm.sh --concurrency 2 --delay-min 3 --delay-max 5 \
  --responses-per-chunk 400 --cooldown-min 180 --cooldown-max 300
```

六个网站均默认使用服务器直连。需要人工切换固定代理时，代理凭据只从
`HUAXIN_PROXY_USERNAME/HUAXIN_PROXY_PASSWORD` 读取；交互终端未设置时会提示输入，
不会写入日志、JSON 或命令行。

## 续跑和附件

每个网站有独立锁和 JOBDIR。Ctrl-C 会先向 Scrapy 转发 SIGINT，已完成的 JSON、CSV、
快照和去重索引均保留。再次执行相同范围会复用 JOBDIR 并跳过已成功导出的公告。

附件阶段使用稳定的“网站/公告类型/公告 ID/源文件 ID”路径。完整文件直接复用，
未完成文件保留 `.part` 并尝试 HTTP Range 续传；默认连接超时 30 秒、流读取超时
900 秒、重试 4 次。可通过以下参数调整：

```bash
./run_sxjm.sh --phase attachments \
  --attachment-connect-timeout 60 \
  --attachment-read-timeout 1200 \
  --attachment-retries 5
```

## 输出与字段

所有结果固定位于 `new_output/<site>/`：

- `json/`、`csv/`：统一八类结构；
- `snapshots/`：详情 HTML 快照；
- `attachments/`：附件二进制；
- `state/`：JOBDIR、去重、完成标记和回填审计；
- `logs/`：终端同步实时日志。

八类公告均包含独立的 `项目编号`、`招标编号`，并保留项目关键字段表要求的原组合字段。
关联顺序为项目编号、招标编号、项目名称。源公告没有某个编号时保存空值，不进行无依据
复制；原始 HTML、正文、接口 payload、字段来源和 SHA256 均保留在快照与 `_trace` 中。
