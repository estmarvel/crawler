# 前后端服务器启动与访问指南

## 1. 当前运行架构

项目目录：`/home/intsig/ProjectRecommendationSystem`

| 服务 | 监听地址 | 端口 | 数据/输出 |
| --- | --- | ---: | --- |
| MySQL | `127.0.0.1` | 3306 | `crawler` 数据库 |
| Express API | `0.0.0.0` | 3001 | Prisma 读取 `crawler` |
| 用户推荐端 | `0.0.0.0` | 8800 | `dist/` |
| 管理端 | `0.0.0.0` | 8802 | `dist-admin/` |

MySQL 只监听本机是合理的：数据库只需要被同一台服务器上的 API 访问，不应直接暴露到公网。

## 2. 重要说明

- 当前 API 已改为读取真实的 `crawler` 数据库，不再把 `project_recommendation` 作为运行数据库。
- `crawler_prisma/prisma/schema.prisma`、迁移后的真实库结构和 API 使用的 Prisma Schema 已核对一致，无需再次建表。
- 日常启动不要执行 `db:seed`，该命令用于旧演示数据，可能污染或覆盖真实数据。
- 日常启动不要执行 `db:push`、`db:migrate` 或 `prisma:deploy`。以后确实需要调整真实库结构时，应先审查迁移 SQL 和备份数据库。
- 现有 `mysql8` 容器就是实际数据库，不要运行项目根目录的 `npm run db:up` 创建另一套旧测试库。

## 3. 启动前检查

```bash
cd /home/intsig/ProjectRecommendationSystem
docker ps
```

正常应能看到名为 `mysql8` 的容器。如果容器已存在但已停止：

```bash
docker start mysql8
```

后端配置文件为 `api/.env`，运行数据库地址应指向：

```dotenv
DATABASE_URL="mysql://app_user:app_password@127.0.0.1:3306/crawler"
API_HOST=0.0.0.0
API_PORT=3001
```

## 4. 构建与启动后端 API

首次安装或依赖有变化时：

```bash
cd /home/intsig/ProjectRecommendationSystem/api
npm install
npm run prisma:generate
```

构建并启动：

```bash
cd /home/intsig/ProjectRecommendationSystem/api
npm run build
npm start
```

`npm start` 会自动加载 `api/.env`。启动成功会显示：

```text
API listening on http://0.0.0.0:3001
```

在服务器本机验证：

```bash
curl http://localhost:3001/api/health
curl http://localhost:3001/api/admin/overview
curl http://localhost:3001/api/admin/collection
curl 'http://localhost:3001/api/admin/projects?page=1&pageSize=5'
```

## 6. 构建与启动管理端

```bash
cd /home/intsig/ProjectRecommendationSystem
npx vite build --config vite.admin.config.ts
serve -s dist-admin -l tcp://0.0.0.0:8802
```

管理端使用 Hash 路由，实际路径如下：

| 页面 | 浏览器路径 |
| --- | --- |
| 管理概览 | `http://<服务器可访问地址>:8802/#/overview` |
| 采集中心 | `http://<服务器可访问地址>:8802/#/collection` |
| 异常处理 | `http://<服务器可访问地址>:8802/#/exception` |
| 项目池 | `http://<服务器可访问地址>:8802/#/project-pool` |
| 数据来源 | `http://<服务器可访问地址>:8802/#/data-source` |

构建产物会同时生成 `index.html` 和 `admin.html`，因此原来的 `http://<服务器可访问地址>:8802/admin.html#/overview` 也仍然可用。推荐使用上表中的根路径形式。

前端未设置 `VITE_API_BASE_URL` 时，会自动使用“当前浏览器访问的主机名 + 3001 端口”请求 API。例如通过 `http://192.168.122.3:8802` 打开管理端时，页面会请求 `http://192.168.122.3:3001/api`。

## 7. localhost 和服务器 IP 的区别

`localhost` 表示“当前正在访问它的机器”：

- 在服务器终端执行 `curl http://localhost:3001/api/health`：正确，访问的是服务器自身。
- 在自己的电脑浏览器中打开 `http://localhost:8802`：通常错误，它访问的是自己的电脑，不是服务器。

当前服务器环境能观察到的私网地址是 `192.168.122.3`。只有当你的电脑能路由到该私网时，才可直接访问：

```text
http://192.168.122.3:8800/
http://192.168.122.3:8802/#/overview
http://192.168.122.3:3001/api/health
```

如果服务器位于云主机、虚拟机或 NAT 后面，应把上面的地址替换成服务器公网 IP、域名或宿主机映射地址，并确保 TCP 端口 `3001`、`8800`、`8802` 已放行。无法开放端口时，也可以使用 SSH 本地端口转发。

## 9. 状态检查与停止

检查监听端口：

```bash
ss -tlnp | grep -E '3001|3306|8800|8802'
```

前台运行时使用 `Ctrl+C` 停止对应服务。生产环境建议下一步使用 systemd 或进程管理器托管 API 和静态站点，并通过 Nginx 统一反向代理，这样浏览器只需访问一个域名，也无需直接暴露 3001 端口。
