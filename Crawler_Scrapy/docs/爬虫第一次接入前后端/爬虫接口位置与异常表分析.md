# 爬虫接口位置与异常表分析

> **已过时（2026-07-27）：** 本文第 4、5 节是异常详情、对象级异常、真实影响公告和自动关闭原异常实现前的分析，已被后续代码替代。HTTP 407 结论、当前出口模式和异常边界已合并到《数据库修改与接口变更汇总说明》。

## 1. 接口调用链

完整路径如下：

```text
管理端按钮
  -> src/services/api.ts
  -> /api/admin/crawler/*
  -> api/src/modules/admin/crawler/crawler.routes.ts
  -> crawler.controller.ts / crawler.service.ts
  -> crawler.runtime.ts
  -> Crawler_Scrapy/run_tws_history.sh
  -> huaxin.py / jiubang.py
  -> StaticProxyMiddleware 或 TianqiProxyMiddleware
```

API 没有复制公告请求、解析、附件或代理认证逻辑。它只负责参数校验、任务状态、进程控制、日志、导入和异常持久化，实际采集仍由 `Crawler_Scrapy` 完成。

## 2. HTTP 407 结论

历史日志表明 2026-07-16 固定代理曾正常完成华新和玖邦采集；2026-07-24 的失败发生在代理建立 HTTPS CONNECT 隧道时，代理服务器直接返回 407。请求尚未到达公告网站，因此不是华新或玖邦的登录、Token 或反爬响应。

固定代理认证仍复用 `StaticProxyMiddleware`，由它生成 Basic `Proxy-Authorization`。407 表明代理服务拒绝当前账号或密码。该失效代理现已停用，当前默认出口改为受控服务器直连：

- `CRAWLER_OUTBOUND_MODE=direct`：使用服务器公网 IP，单并发、5 秒随机延迟、AutoThrottle、零普通重试，首次连续 403/429 主动停爬。
- `CRAWLER_OUTBOUND_MODE=static`：使用固定代理，需要有效的 `HUAXIN_PROXY_USERNAME/PASSWORD`。
- `CRAWLER_OUTBOUND_MODE=tianqi`：使用现有天启代理池，需要有效的 `TIANQI_SECRET/SIGN`。

CONNECT 407 现在会停止无效重试，并在数据库记录为 `PROXY_AUTHENTICATION`；凭据缺失和代理网络失败分别记录为 `PROXY_CONFIGURATION`、`PROXY_UNAVAILABLE`；服务器出口收到 403/429 并主动停爬时记录为 `ACCESS_BLOCKED`。

## 3. 是否需要独立异常表

需要。`crawl_task.error_message` 只表示一次任务的最终错误摘要，不能承载待处理、处理中、已解决、已忽略、处理人、处理备注和重试次数。管理端需要完整的处置流程，因此独立 `crawl_exception` 比继续扩展 `crawl_task` 更合理。

当前表已经能支持任务级异常的基础展示和操作：异常来源、类型、错误消息、状态、任务关联、数据源、重试次数、处理人、备注和解决时间；前端已能查询、重试、忽略和标记解决。

## 4. 当前逻辑的不足

当前实现只能完整处理“任务执行异常”，还不能完全满足文档所列的全部异常场景：

1. `raw_notice.parse_status`、原始附件和项目公告附件错误仍由旧统计接口动态识别，没有同步进 `crawl_exception`，因此异常处理页看不到完整解析/附件异常。
2. `source_type/source_ref` 是多态字符串，没有公告、附件、项目的真实外键，数据库无法保证关联对象存在。
3. 缺少 `severity`、`error_code`、`stage`、`occurred_count`、`last_occurred_at`、`retry_task_id` 等字段，无法准确展示严重等级、发生阶段、重复次数和重试结果。
4. 重试只把原异常改为 `PROCESSING` 并增加 `retry_count`，但没有在重试任务成功后自动关闭原异常；前端“自动重试成功”实际统计的是重试发起次数。
5. 前端影响条数目前固定为 1，近七日趋势最多基于最近 100 条异常，数据量增加后统计会不准确。
6. 管理概览仍使用 `/api/admin/exceptions` 动态拼装异常，而异常处理页使用 `/api/admin/crawler/exceptions`，两个页面口径不一致。

## 5. 建议

保留 `crawl_exception`，不要退回仅使用 `crawl_task.error_message`。下一步应让任务、公告解析、附件下载和数据导入都通过统一异常服务写入该表，并补充错误阶段、严重级别、重复次数及重试任务关联；管理概览与异常处理页统一读取持久化异常接口。完成这些调整后，前端才能按要求稳定展示完整异常闭环。
