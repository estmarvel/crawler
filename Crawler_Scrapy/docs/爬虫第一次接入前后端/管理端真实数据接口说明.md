# 管理端真实数据接口说明

> **已过时（2026-07-27）：** 本文中项目、任务、计划和数据源的大部分参数仍有历史参考价值，但概览/采集漏斗仍使用旧业务表口径，第 4 节称 Schema 没有异常表已经错误，且文档缺少异常详情接口。当前完整接口契约已合并到《数据库修改与接口变更汇总说明》。

## 1. 通用约定

API 基础地址：

```text
http://<服务器地址>:3001/api
```

服务器本机调试可使用 `http://localhost:3001/api`。

成功响应统一结构：

```json
{
  "code": 0,
  "data": {},
  "message": "ok"
}
```

失败响应统一结构：

```json
{
  "code": 400,
  "data": null,
  "message": "错误原因"
}
```

除特别说明外，日期时间字符串格式为 `YYYY-MM-DD HH:mm:ss`，日期格式为 `YYYY-MM-DD`。

## 8. 已实现：爬虫控制接口

### 8.0 采集源管理

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/admin/crawler/data-sources?page=1&pageSize=10` | 分页查询全部采集源；可传 `isEnabled=true/false` |
| `POST` | `/api/admin/crawler/data-sources` | 新增一条 `data_source` |
| `PATCH` | `/api/admin/crawler/data-sources/:id` | 编辑指定采集源 |

新增请求示例：

```json
{
  "name": "示例采购平台",
  "shortCode": "example_platform",
  "baseUrl": "https://example.com/",
  "sourceLevel": "企业",
  "province": "山西",
  "crawlFrequencyMinutes": 60,
  "crawlConfig": null,
  "isEnabled": false
}
```

列表返回 `items/total/page/pageSize`。每条记录除数据库字段外，还包含 `crawlerSupported`、`status`、`activeTaskId`、`todayCount`、`totalCount` 和 `successRate`。停用数据源不会被过滤。`shortCode` 必须唯一，只允许字母、数字、下划线和连字符；禁用存在等待或运行任务的数据源会返回 HTTP 409。

新增数据源只代表登记和维护配置。当前任务运行接口仍只允许已实现 Spider 的 `data_source.id=6/14`，其他记录的 `crawlerSupported=false`，不会进入管理端的新建任务下拉框。

当前只支持 `dataSourceId=6`（huaxin）和 `dataSourceId=14`（jiubang）。一个任务只对应一个数据源；同一数据源不能同时运行两个任务，但可以建立多个未来预约任务。任务、计划、事件和异常时间字段在本组接口中按 JSON 标准返回 ISO 8601 字符串。

任务类型只允许 `INCREMENTAL`、`HISTORY_RANGE`、`HISTORY_FULL`，详细语义见《爬虫任务类型与运行异常说明》。栏目只允许 `zbgg_zys`、`hxr`、`gs`、`zbjh`。

### 8.1 创建任务

- 方法：`POST`
- 路径：`/api/admin/crawler/tasks`
- 立即执行：不传 `scheduledAt`，或传入当前/过去时间
- 单次预约：传入未来的 `scheduledAt`

管理端“采集任务管理”的“新建采集任务”按钮直接调用本接口。表单先选择 `taskType`，再选择“立即执行”或“预约执行”；它不是只能创建定时任务。周期重复执行属于第 9 节的计划接口。

```json
{
  "dataSourceId": 6,
  "taskType": "INCREMENTAL",
  "scheduledAt": "2026-07-25T01:00:00+08:00",
  "options": {
    "lookbackDays": 1,
    "sections": ["zbgg_zys", "hxr", "gs", "zbjh"],
    "pageSize": 10,
    "maxRecords": 5,
    "maxPages": 1,
    "timeoutMinutes": 30,
    "importData": true
  }
}
```

`HISTORY_RANGE` 必须传 `options.startDate`，可传 `endDate`，格式均为 `YYYY-MM-DD`。`HISTORY_FULL` 忽略日期参数。返回 HTTP 201 和完整任务对象。

新建任务时 `options.sections` 必填；`INCREMENTAL` 还必须提交 `lookbackDays`。`pageSize`、`maxRecords`、`maxPages`、`timeoutMinutes` 和 `importData` 可选，默认分别为 `100 / 1000000 / 10000 / 720 / true`。这些较大的记录数和页数用于表达“采集完整时间范围”，爬虫通常在源站最后一页自然结束。校验上限为：`lookbackDays<=3650`、`pageSize<=100`、`maxRecords<=1000000`、`maxPages<=100000`、`timeoutMinutes<=10080`。

任务结束后，`importData=true` 会执行完整的幂等流水线：`raw_notice`、`raw_notice_attachment`、`notice_extraction`、`project`、`project_notice`、`project_notice_attachment`。当前明确跳过 `project_requirement` 和推荐计算。

### 8.3 停止任务

- 方法：`POST`
- 路径：`/api/admin/crawler/tasks/:id/stop`
- Body：无

`PENDING` 任务直接变为 `CANCELLED`。`RUNNING` 任务先变为 `CANCEL_REQUESTED`，API 只向本进程启动并仍在管理的进程组发送 `SIGTERM`，进程退出后变为 `CANCELLED`。为避免 PID 复用误杀，API 重启后不会根据数据库中的旧 PID 杀进程。

管理端对尚未启动的 `PENDING` 任务显示“取消”，调用时不弹确认框；取消后依据 `startedAt=null` 显示“已取消”。启用、重试或再次执行预约任务时，如果原 `scheduledAt` 仍在未来，新任务继续使用该时间；如果已过期，页面提示后不传 `scheduledAt`，新任务立即执行。

### 8.4 任务日志

轮询接口：

- 方法：`GET`
- 路径：`/api/admin/crawler/tasks/:id/logs`
- Query：`lines`，默认 200，范围 1–2000
- 返回：`events` 为结构化关键事件；`logTail` 为 Scrapy 日志末尾文本

实时接口：

- 方法：`GET`
- 路径：`/api/admin/crawler/tasks/:id/logs/stream`
- 协议：Server-Sent Events（`text/event-stream`）
- 事件：`status`、`log` 和 `stage`；连接每 15 秒发送心跳

管理端采集中心已接入该 SSE：存在运行任务时自动追加真实 Scrapy 输出；没有运行任务时继续展示数据库任务汇总。

## 9. 已实现：固定间隔调度

### 9.1 查询与创建计划

| 方法 | 路径 |
| --- | --- |
| `GET` | `/api/admin/crawler/schedules` |
| `POST` | `/api/admin/crawler/schedules` |

创建 Body：

```json
{
  "dataSourceId": 14,
  "name": "玖邦每日增量采集",
  "taskType": "INCREMENTAL",
  "intervalMinutes": 1440,
  "nextRunAt": "2026-07-25T01:00:00+08:00",
  "isEnabled": true,
  "options": {
    "lookbackDays": 2,
    "sections": ["zbgg_zys", "hxr", "gs", "zbjh"],
    "pageSize": 50,
    "maxRecords": 200,
    "maxPages": 10,
    "timeoutMinutes": 720,
    "importData": true
  }
}
```

`intervalMinutes` 范围为 5–525600。前端允许用分钟、小时或天设置固定频率，提交时统一换算为分钟；新建计划修改频率时，`nextRunAt` 自动取浏览器当前时间加该频率。计划的数量限制参数与普通任务一样可选；增量计划必须额外提交 `lookbackDays`，指定范围计划必须提交 `startDate`、可提交 `endDate`。调度器每 15 秒检查到期计划，并根据计划新建独立 `crawl_task`。

### 9.2 修改或停用计划

- 方法：`PATCH`
- 路径：`/api/admin/crawler/schedules/:id`
- Body：至少传 `name`、`intervalMinutes`、`nextRunAt`、`isEnabled`、`options` 中的一项
- 停用示例：`{ "isEnabled": false }`

### 9.3 删除计划

- 方法：`DELETE`
- 路径：`/api/admin/crawler/schedules/:id`
- Body：无
- 返回：`{ "id": 计划ID }`

删除只移除 `crawl_schedule`。由该计划生成的历史 `crawl_task` 不会删除，其 `schedule_id` 根据外键规则自动设为 `NULL`；已经运行中的任务也不会因为删除计划而被强制停止。

## 10. 已实现：持久化异常接口

### 10.1 查询异常

- 方法：`GET`
- 路径：`/api/admin/crawler/exceptions`
- Query：`status` 可选 `OPEN`、`PROCESSING`、`RESOLVED`、`IGNORED`；以及 `page`、`pageSize`

任务启动、运行或导入失败时自动写入 `crawl_exception`。返回字段包括异常 ID、任务 ID、数据源、异常类型、消息、处理状态、重试次数、处理人、备注及时间。

### 10.2 更新处理状态

- 方法：`PATCH`
- 路径：`/api/admin/crawler/exceptions/:id`

```json
{
  "status": "RESOLVED",
  "handledBy": "管理员",
  "remark": "代理恢复后验证通过"
}
```

### 10.3 重试失败任务

- 方法：`POST`
- 路径：`/api/admin/crawler/exceptions/:id/retry`
- Body：无
- 仅任务异常且原任务处于 `FAILED`、`CANCELLED`、`TIMED_OUT`、`PARTIAL_SUCCESS` 时可重试
- 返回 HTTP 201：`{ "taskId": "4", "exceptionId": "1" }`

重试会复制原任务的采集范围和限制参数，创建新的任务；原任务不会被覆盖。创建新任务、六阶段记录、CREATED 事件以及异常改为 `PROCESSING` 在同一事务中完成。正在处理的异常不能重复重试。重试成功后原异常自动改为 `RESOLVED`，失败或取消则恢复为 `OPEN`。

管理端异常处理页已接入持久化异常列表、重试、忽略和标记已解决操作。原 `/api/admin/exceptions` 仍用于管理概览等兼容查询。
