- 管理端哪些页面需要真实爬虫数据

- 建议落到哪些 Prisma 表和字段

## 一、当前需要对齐的管理端模块

当前管理端里，最相关的只有这 4 个：

1. 管理概览
2. 采集中心
3. 异常处理
4. 项目池

说明：

- `项目池` 已经接了真实后端 API，但前提是服务端真实数据要落到 `Project`
- `管理概览 / 采集中心 / 异常处理` 目前基本都还是 mock 或写死数据

## 三、最关键的 schema 表匹配结论

Prisma 表对接价值可支撑哪些页面关键字段当前不足DataSource高采集中心、异常处理name/shortCode/baseUrl/sourceLevel/province/crawlFrequencyMinutes/isEnabled缺少直接展示用聚合字段CrawlTask很高采集中心、异常处理、管理概览status/scheduledAt/startedAt/finishedAt/totalCount/successCount/failCount/errorMessage缺少人工处理流字段RawNotice很高管理概览、采集中心、异常处理sourceUrl/sourceNoticeId/title/publishDate/crawlTime/parseStatus缺少明确解析失败详情字段RawNoticeAttachment中异常处理、质量类页面fileName/fileUrl/fileType/parseStatus缺附件级错误详情NoticeExtraction高管理概览、异常处理、人工审核noticeType/extractedFields/confidenceScore/isVerified缺审核状态流、备注Project很高项目池、管理概览projectName/province/city/industry/ownerCompanyName/agencyCompanyName/tenderAmount/bidOpenTime/currentStatus/firstPublishDate需数据方确认ProjectNotice高项目池来源展示、原文链接noticeType/title/sourceSite/sourceUrl/publishDate/crawlTime当前项目池接口未联查RecommendationResult中高今日推荐输出、推荐结果统计matchScore/winProbability/recommendLevel/competitionLevel/reason/risk/createdAt基本够用UserFavorite中收藏状态、用户行为userId/projectId/status/note当前不在本轮重点

### 关键结论

1. `Project` 已经足够支撑当前项目池页面主体展示
2. `DataSource + CrawlTask + RawNotice` 是采集中心和异常处理真实化的核心
3. `ProjectNotice` 负责“来源网站/原文链接/公告层信息”
4. `RecommendationResult` 可以支撑“今日推荐输出”
5. 当前 schema **没有完整的异常处理流表**，大概率需要新增异常表或补字段

```
notice_extraction`、`raw_notice_attachment`、`project_requirement`、`project_notice_attachment`，需要爬取的字段保存在`project_notice.structured_data
```

`DataSource.name`和`ProjectNotice.sourceSite`是一样的，用这个
